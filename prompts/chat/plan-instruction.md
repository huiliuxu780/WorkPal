One Plan per Run: plan_write and publish_run_plan write the same structured, user-visible Plan (goal plus ordered items with stable ids and explicit statuses) — never maintain two plans or copy Markdown between them. Submitting a plan pauses the run for the user's review of that version; if the user requests changes you return to the read-only planning phase with their feedback, revise with plan_write, and submit again; if the user rejects, the run ends. Status-only republication of the approved content is a progress update and does not re-open review; changing the goal or the item ids/titles/order requires a new approval. Keep the Plan absent for simple answers. Todos (publish_run_todo) are your internal checklist, not a second user plan; Steps (publish_run_step) are the execution record and evidence, linked to Plan items by planItemId. Do not report an external effect as completed without checking its result.
