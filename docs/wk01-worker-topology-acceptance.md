## 2. Topology under acceptance

Six identifiable processes/containers, recorded with pids in `test-report/worker-chain/summary.json`:

1. **API/Web backend** — the CLI harness process serves `apps/api` via `@hono/node-server` on `127.0.0.1:3120`; `WAKEUP_DRIVER=graphile`, so it **publishes jobs only** (no job handlers, no reconciler — those exist only in `apps/worker` graphile mode). `/internal/health` is asserted at startup to report `runtime=agentscope` and `jobs=graphile` (never the scripted/memory assertions).
2. **Worker** — `pnpm exec tsx apps/worker/src/index.ts` child process (detached process group; SIGKILL kills the whole tree), production entrypoint with the production sweeps: budget (10s), delivery dispatch (10s), reconciler (30s, Postgres advisory leadership), abort retries (10s). Lifecycle controlled through harness-layer `/__e2e/worker/{status,start,stop}` served by the CLI's fetch wrapper — **no `apps/api` production code is touched**. Generations are numbered; each generation logs to `worker-<n>.log`.
3. **Java AgentScope runtime** — `java -jar agent-runtime-0.1.0.jar` child process (JDK 21, loopback port, own data dir), reached by both API and Worker through `AGENTSCOPE_URL`.
4. **PostgreSQL** — Testcontainers `postgres:16-alpine`, or an external local `workpal_e2e_*` database via `WORKPAL_E2E_DATABASE_URL` (recreated pristine per run).
5. **Web** — vite dev child of the Playwright `webServer` on `127.0.0.1:5190`, proxying `/api`+`/rpc` to the API.
6. **Model fixture** — loopback OpenAI-compatible emulator (`packages/testkit/src/model-emulator.ts`) inside the Playwright spec process; connected through the production `models/connect` RPC as the user's encrypted credential; Java reaches it over loopback. Request log is asserted per test.

Process-identity correlation (acceptance 1–2): a Run's `leaseOwner` is `${nodePid}-${uuid}` of the real Worker node process; specs assert that pid is (a) in `pgrep -f apps/worker/src/index.ts`, (b) not the API/spec pid, not `"api"`, and (c) present in the `generation-ready` line the harness writes into **that Worker generation's own log** — tying DB rows, Worker logs and fixture requests to the same Run.

### Criterion mapping

1. **Separate processes / agentscope health** — CLI `/internal/health` assertion (`runtime=agentscope`, `jobs=graphile`) + per-spec `assertTopologyHealth()` + leaseOwner↔pgrep↔worker-log pid correlation in every test; Worker env pins `AGENT_RUNTIME=agentscope`; scripted is impossible (production guard + CLI constant).
2. **Queued while down, same Run claimed, interrupted recovery** — Test 1: 8s of polling proves `queued`, zero Attempts and **zero model-fixture requests** while the Worker is stopped; after start, the same Run ID is leased by a Worker pid, runs, completes, one Attempt. Test 4: SIGKILL mid-model-call; the orphaned Run stays `running` with the dead lease (nothing finalizes without a Worker, no model activity, no reply in the transcript). This test uses **no clock seam at all**: it waits out the real hard-coded 5-minute run-lease and computer-execution-lease TTLs on the production clock. Recovery then runs end to end in production code — the restarted Worker's reconciler re-enqueues `run.continue` (graphile replace-mode `add_job` natively supersedes the killed job's stale lock), the lease-loss path aborts the orphaned Java session and schedules the automatic `lease_lost` retry (`run.retried`, Attempt fence 1 → `retry_scheduled` with the lease-expired error), the expired computer-execution lease is reclaimed, and the **new Worker generation** (pid proven from DB + that generation's log) re-executes the same Run under a fresh fence to completion; actual recovery duration measured and recorded (~5-6.5 min, dominated by the lease TTLs by design).
3. **Proactive delivery through the production outbox** — Tests 2/3: Routine created and fired through the product RPCs (`routines/create` + `routines/testRun`, `trigger=routine`); the Worker's own budget sweep enforces the rewound duration budget (no in-process `enforceRunBudgets` call); the production transaction writes `budget.exceeded → run.failed → delivery.created` and the `run_result` DeliveryRecord (idempotencyKey `<runId>:budget_failure`); the Worker's dispatch sweep claims after the 30s merge window and creates the `trigger=delivery` Run executed by the same standalone Worker (lease pid proven); ID chain asserted end to end: `delivery.created{deliveryId,sourceRunId}` → delivery Run → exactly one bot `Message(runId=deliveryRun)` → `delivery.sent{deliveryId,messageId}` with seq order. **No new user message anywhere** (user-message count asserted unchanged), no dispatcher call, no fabricated result.
4. **Exactly once under duplicate scheduling and restarts; isolation; honesty** — Test 2: after settle, ≥2 extra dispatch sweeps and then a full Worker stop/start leave exactly 1 delivery Run, 1 `delivery.sent`, 1 visible bot message, record stays `sent`. Test 3: Worker SIGKILLed inside the merge window — during downtime past `nextAttemptAt` the record stays `pending`/unclaimed, zero delivery Runs, zero messages, **zero model requests**; after restart the durable row alone drives exactly-once delivery. Cross-Space isolation: a second signed-up user (fresh Space/Thread) sees nothing — no delivery Runs/records/`delivery.sent` events outside the origin Thread, no `DELIVERY_TEXT` in its transcript or messages, distinct `spaceId`. Pre-completion crashes never report success (Test 3 downtime assertions; Test 4 asserts nothing finalizes while the Worker is dead).
5. **Gates** — `pnpm --filter @rakazo/testkit check` green; spec typechecked (tsc, strict); biome clean; the jar is rebuilt by `startJavaRuntime` unless `AGENT_RUNTIME_SKIP_BUILD=1` (CI reuses the `mvn package` artifact); the suite recreates its database and removes the Java data dir, worker logs and containers on exit.

Gates run for this slice: `pnpm --filter @rakazo/testkit check` (tsc) green; spec strict tsc (ad-hoc project, `--strict --noUnusedLocals`) green; biome format/lint clean; the Java jar was rebuilt from this branch by `startJavaRuntime` (`mvn package -DskipTests`, JDK 21) in every local round — no Java source changed, so CI reuses the `agentscope` job's `mvn package` artifact via `AGENT_RUNTIME_SKIP_BUILD=1`. **Zero production application code changed**: the slice touches testkit (CLI, java-runtime pid, emulator destroyed-guard), the e2e spec, compose files, CI wiring and docs only — `apps/api` gained no routes (Worker control lives in the harness fetch wrapper), `apps/worker`/`packages/adapters`/`services/agent-runtime` are untouched. ## 4. Test seams (metering facts only)

Same class as `budget-acceptance.spec.ts`; every Run/message/outbox/retry is still produced by production code in the Worker process:

- **Attempt clock rewind** (`startedAt −3601s`) to cross the 3600s unattended duration budget — the Worker's own sweep does the enforcement.
- **No lease/graphile seams** — the mid-run crash test waits out the real 5-minute run-lease and computer-execution-lease TTLs; the reconciler re-enqueue, graphile's replace-mode supersede of the SIGKILLed job's stale lock (F3), the lease-loss abort/retry policy and the computer-lease reclaim are all exercised as production code on the production clock.
- **Bounded native DELETE** (`releaseNativeRun`, mirrors the production `retryPendingRunAborts` sweep) to guarantee the Java thread session slot is free before the delivery Run; idempotent, and normally a no-op because the Worker's enforce-time abort already landed.
- **Harness-layer `/__e2e/worker/*`** process lifecycle endpoints, served by the CLI's fetch wrapper (same layer as `/__e2e/emails`); no production route added.
- **Held fixture streams** (`type: "hold"`) to make claim/lease/delivery windows deterministic; released by the spec or closed by production aborts.

## 5. Infra findings and minimal fixes (task card: report + minimal correction)

- **F1 — scripted topology smoke was dead on arrival.** `docker-compose.topology.yml` set `NODE_ENV: production` with `AGENT_RUNTIME: scripted`; the production guard added in `b506405` makes both api and worker throw at boot, so `pnpm test:topology` could not have passed since that commit. Fix: compose anchor now sets `NODE_ENV: test` (this smoke *is* the deterministic test the guard reserves scripted for); no application code changed; `topology.ts` assertions unchanged. Verification: the guard collision and its removal are the direct code path quoted above; a full `pnpm test:topology` re-run on this host was **blocked by Docker Hub connectivity** (the colima daemon has no registry mirror and could not pull `node:22-bookworm`; three retries failed with EOF/auth errors). The rest of the smoke flow is unchanged from its last known-green run, and the topology smoke is not part of PR CI; repeat the rerun on a host with registry access.
- **F2 — stale Python overlay broke the production deploy path.** `infra/compose/docker-compose.prod.agentscope.yml` still defined `agentscope` with the removed `services/agentscope/Dockerfile` (Python runtime). Because `deploy-workpal.sh` layers it over `docker-compose.prod.yml` — whose base **already** carries the Java runtime service and the api/worker `AGENT_RUNTIME=agentscope`/bridge env — any deploy since the Java migration would fail at build and auto-rollback; production may be pinned to a pre-migration revision (operator should verify `.last-deployed-revision` on the ECS host). Fix: the overlay is reduced to its only remaining delta over the base (the `:8080` plain-HTTP publication used by `Caddyfile.ip-http`), with the history recorded in its header. Deploy layering (`-f` order) is unchanged.
- **F3 — mid-run crash wake-up is fast and fully production-borne (verified, corrected finding).** Initial code reading suggested a SIGKILLed worker's locked in-flight job would block `run:<id>` re-enqueues until graphile's 4-hour `resetLockedAt` sweep (the runner sets no `jobLockDuration`). Deeper verification of graphile-worker 0.17.3's `add_job` disproved this: a replace-mode enqueue against a locked job **neuters the stale row** (`key = NULL, attempts = max_attempts`, `is_available` is generated as `locked_at IS NULL AND attempts < max_attempts`) **and inserts a fresh job**. So after a Worker restart the reconciler's `run.continue` enqueue (≤30s) immediately re-wakes the lease-expired Run; test 4 measures the whole recovery (restart → `run.retried` → fence-2 re-execution → completion) with no graphile seam. Residual graphile nuance (cosmetic, no run impact): an orphaned locked row that nobody ever re-enqueues is only garbage-collected by the 4-hour sweep.

## 6. How to run

```bash
# JDK 21 on PATH (e.g. export JAVA_HOME=/opt/homebrew/opt/openjdk@21), Docker for
# Testcontainers OR a local Postgres with a disposable workpal_e2e_* database:
export WORKPAL_E2E_DATABASE_URL="postgres://user:pass@127.0.0.1:5433/workpal_e2e_worker_chain"
```

Costs: 1 JVM (~600MB), 1 Postgres container or external DB, 1 vite child, 1 Chromium (Playwright), API+Worker node processes; ports 3120 (API) / 5190 (Web), overridable via `WORKER_CHAIN_API_PORT` / `WORKER_CHAIN_WEB_PORT`. Artifacts: `test-report/worker-chain/` — `summary.json` (process inventory + pids + health), `spec-timings.json` (measured recovery/latency), `worker-<n>.log` per generation, API/worker data dirs (removed on exit). CI: runs inside the existing `agentscope` job (ubuntu-latest, Docker available) after the resident e2e specs; adds roughly the suite wall-time to that job.

## 7. Limitations

- Proves the **Routine over-budget → outbox** proactive-delivery chain and the Worker deployment boundary. It does **not** claim native-helper background results are verified in a production topology: AG-02's delegation suspension stays in force and WK-01 did not re-enable it (the pre-WK-01 WIP scenario that used `agent_spawn` was replaced, not resurrected).
- The model is a deterministic protocol fixture: this proves execution, recovery and delivery mechanics, not model behavior.
- The 3600s unattended budget is simulated by an Attempt-clock rewind (metering fact); the 5-minute run/computer lease TTLs are **waited out for real** in test 4, which is why that test adds ~5-7 minutes to the suite — the measured recovery time is the true production latency for a mid-run crash. The graphile stale-lock supersede semantics are verified from the installed SQL (`add_job` in graphile-worker 0.17.3) and exercised end-to-end by the same test.
- The scripted compose topology fix (F1) is verified by code-path analysis on this host only — the full compose smoke rerun was blocked by Docker Hub connectivity (see F1); repeat it where the registry is reachable.
