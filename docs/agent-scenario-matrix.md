# Agent scenario matrix

WorkPal-specific map of **trigger → prompt family → model-visible tools → executable case → evidence**. This is the repository-maintained successor of the external baseline (`myagent/docs/workpal-baseline/agent-scenario-matrix.md`), reconciled line-by-line against `main @ c2dfea4` on 2026-10-19 by [AG-03](./tasks/AG-03.md). It links the [prompt inventory](./agent-prompt-inventory.md), the executable [case registry](../packages/adapters/src/__fixtures__/scenarios/case-registry.ts) and the [AG-03 delivery note](./ag03-scenario-contracts.md). A `Task`/`Run` is an execution record within a Bot's durable Thread, not a new user-managed conversation.

This document describes implemented paths and recorded findings; it does not authorize new behavior. Every row has case IDs; every case has evidence that runs offline (no paid inference).

## Reading the matrix

- **Backend-selected** means the application chooses a model from the current Bot/user/deployment configuration.
- **Model-visible tools** are captured at the real TS adapter → Java runtime → local model fixture request boundary, or asserted against frozen literals derived from `selectBuiltinToolsForRun` plus the Java native surface. "Empty" always means empty **including Java natives**.
- Captured fact: `run_subagent` remains in the TS selection for chat runs but is never registered or exposed by the Java runtime (AG-02 suspension), so it never appears in a model-visible set.
- Captured fact: the chat-scope native `load_skill_through_path` is registered only when the request carries skills; production chat requests carry the default skill set, so it is visible on ordinary chat runs and on the created intro, but not on delivery runs (`skills: []`).
- Prompt family IDs (P01–P14) come from the [inventory](./agent-prompt-inventory.md); family markers are pinned in the registry and asserted against production composers. Since AG-04, fixed bodies live in [`prompts/`](../prompts/README.md) and the registry maps every family to its stable segment IDs (`PROMPT_FAMILY_SEGMENTS`).
- Evidence layers: `unit` (offline composers/registry), `integration` (real jar + model fixture), `postgres` (full app + production executor + PG), `java`, `e2e`.

## Corrections against the external baseline (2026-10-19)

1. **S07 helper availability**: the baseline described native helper delegation as an implemented path. Since AG-02 it is suspended for every Run served by the production HTTP entrypoint (no env bypass); only the in-JVM package-private seam enables it for tests. S07 is now a suspension contract plus separately labeled seam-regression evidence.
2. **S14 judge scope audit closed**: the baseline audit "judge currently lacks explicit auxiliary execution scope" was resolved by AG-01 (`team-chat-judge` scope, Java-enforced zero tools).
3. **P06/S12 provenance audit closed**: text-prefix identification was replaced by typed provenance (AG-07); injections carry `kind: "application"` + `contextKind` on the wire and Java validates them.
4. **Assembly order**: the baseline inventory omitted the AG-06 `<content-trust-rules>` segment. Actual order: platform → content-trust-rules → turn-policy → bot-instructions → collaboration-context (chat only) → runtime-context.
5. **`handoff`/`resume`**: neither creates Runs; `handoff` is a collaboration role, `resume` is declared-only (see classification above).
6. **Versioned segment registry / text-prefix recognition registry** proposed by the old plan §19.3 are superseded by AG-04 (stable IDs for source/test lookup only; Git tracks versions; typed provenance stays the source classifier).
7. **S01 "native Plan/helper tools only if TurnPolicy allows"**: the helper half is obsolete — helper natives are never offered in production regardless of policy; Plan natives still follow TurnPolicy.

Recorded findings from AG-03 execution (pinned by tests, not masked): connector revocation between approval and resume fails the Run at the Java bridge allow-list with the effect left `approved` and zero provider executions (finding A), and the dangling session tool call also fails the next same-thread Run without a model call (finding B). Details and attribution: [ag03-scenario-contracts.md](./ag03-scenario-contracts.md).

## Cross-scenario rules to preserve

1. **Tool visibility is not permission.** Java refreshes a per-call allow-list from `/v1/tool-surface` (AG-05); the authenticated bridge and backend re-check active identity, scope, connector/resource state and capability policy before execution. A changed policy can deny an approved replay (pinned by S09-C3; pending-call recovery is AG-08).
2. **Untrusted text stays data.** Web pages, connector output, peer Bot messages, background results, summaries and recalled memory cannot become user authorization: the fixed AG-06 `<content-trust-rules>` segment plus typed provenance (AG-07) plus per-family untrusted-data framing.
3. **One durable conversation.** PostgreSQL owns complete Thread messages and Product Events. AgentScope state and compaction serve model continuity. Delivery, routine and helper work create Task/Run records, not replacement Threads.
4. **Concurrent outcomes respect generation and effect state.** Thread Clear fences late background delivery; approval replay checks the current policy; retries must not duplicate a confirmed effect.
5. **Unsupported capability remains unavailable.** This matrix does not add periodic memory distillation, side-question calls, multi-agent rooms, dedicated code-intelligence/Office tools or a production Pi fallback.

## How to maintain it

When adding or changing a scenario: update the registry case (ID, families, tool expectation, evidence), the matching row here, and the [inventory](./agent-prompt-inventory.md) family together — the registry integrity test fails when a case loses evidence or a trigger loses classification. Mark work with no production implementation as declared-only/unavailable with the proof pattern used for `reaction`/`resume`; never simulate support. Frozen tool literals are contracts: when a capability legitimately changes, update the literal in the same PR and say why.
