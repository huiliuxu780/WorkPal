# 圆桌模式原型说明

- 目标：主线演示“主持委派 → 成员确认转后台 → 后台仍能发言 → 子委派 → 用户再次 @ 指派 → 局部审批 → 结果回流 → 主持综合”；分支验证主线之外的关键状态。
- 覆盖：需求矩阵共 96 个原子验收场景；原型包含 8 段主故事线和 28 个高价值分支状态。其余场景进入 API、Runtime、投影和端到端测试，不重复画同构页面。
- 分支：顶部“场景”选择器分为用户介入、任务补充、跨会话调度、固定 Agent 对话、并发与时序、审批与权限、异常与恢复七组，每组 4 个；左右箭头可在当前模式内连续切换。
- 任务补充规则：用户必须通过原消息回复、工作树或 task chip 精确指向既有 Task。原 Task 指令不覆盖，补充按 seq 追加；active Run 直接 steering，后台工作由负责人判断继续合并还是取消旧 attempt，同一 Task 已完成时追加 follow-up Run。只写“刚才那个任务”且存在多个候选时先让用户选择。
- 跨会话规则：A 不在目标群但用户有成员管理权时，先显示“加入群并继续”的范围审批；完成后 A 必须回来源单聊单独汇报结论，而不是只放一个完成状态或要求用户自己去群里找。
- Agent 私下通知规则：来源会话只保留一行轻回执，而且它是位于两条消息之间的独立行，不嵌进 Agent 的回复气泡。单目标点击直接打开 A ↔ B 的长期固定对话；多目标点击在原行下方展开紧凑的 Agent 名单，只显示头像和名字，点击名字进入对应双人对话。该对话不进入侧边栏，保留历史，仅供用户查看且没有输入能力。群内公开 `@Agent` 仍留在群 Thread，不与私下对话混用。
- Mention 链接：消息发出后，群里的 `@Agent` 显示为小头像 + 名字的内联链接；点击进入当前用户与该 Bot 的长期单聊，并保留“返回圆桌”。它只做导航，不发送消息、不创建任务，也不进入 Agent ↔ Agent 的固定对话。Agent 停用或用户无访问权时不可跳转。
- 双 Agent 对话形态：打开后是一整张独立浮窗，不使用普通页面导航栏；两个 Agent 的头像、名字和双向关系共同收进浮窗顶部居中的身份胶囊，底部只保留居中的“关闭聊天”。
- 固定对话分支：覆盖反向联系复用同一 Thread、多目标 receipt 先选 pair、同一 pair 多来源并发不串线、Bot 停用后旧历史仍可查看但新投递失败。
- 画布：桌面端 1440×900；窄屏隐藏左侧导航，群详情面板变为覆盖层，场景选择器固定在左下角。
- 视觉：延续 WorkPal 现有浅色、低对比边框、圆角输入框和黑色角色 Avatar；颜色只区分成员和状态，不改变品牌骨架。
- 右栏信息架构：右侧不是一个独占的“圆桌工作”抽屉，而是复用群聊已有的详情面板，在 `详情 / 工作 / 资料库 / 成员` 中新增稳定的“工作”页签。群标题打开“详情”，顶部“工作”、聊天内任务状态与活动胶囊直接打开“工作”；资料库继续保存稳定产物，成员页继续做成员管理，例行任务保留在详情页。四个页签共享同一个右栏，不互相覆盖。工作入口不显示数量：Task、Agent 与 Run 的计数口径不同，数字会制造错误确定性。
- 右栏视觉基线：忠实沿用 Grokbot 已有的 336px 会话详情栏——顶部成员头像簇、居中群名、扁平胶囊页签、白底分隔线和无卡片列表。`工作` 页不得另造标题栏、树状套卡、解释文案或第二层抽屉；只在同一骨架里增加扁平工作行，并在点击后原位切换任务详情。
- 群聊详情入口：群成员头像簇与群名组成聊天区顶部居中的浮动胶囊。点击胶囊展开右侧详情栏；详情栏已展开时再次点击同一胶囊收起。顶部胶囊是右栏总开关，顶部“工作”等窄入口只负责直达对应页签；入口和页签都不显示工作数量。
- 群身份呈现：顶部胶囊和右栏头部使用同一组真实成员头像堆叠，既包含当前用户头像，也包含群内各 Agent 的角色头像；不得用同形圆点代替。右栏群名是无边框文本栏，单击进入编辑，失焦保存，`Enter` 等同保存，`Esc` 放弃本次修改。
- 详情与成员控件：成员是无边框、无分隔线的纵向名单；“添加 Agent”和“设置例行任务”沿用 Grokbot 的左对齐 `＋ 文本`入口，不使用通栏描边按钮或卡片。
- 资料库视觉：复用 Grokbot 的日期分组与无外框文件列表，分组关系由日期标题和留白表达；每行只保留缩略图、名称、更新时间和悬停更多操作。不得把整组资料包成描边卡片，不得改写成“最近产物”信息面板，也不增加逐行“打开”或“查看全部产物”按钮；圆桌产物被保存后按普通资料进入这里。
- 全局与群内边界：侧边栏“后台任务”继续是跨会话的全局任务中心；群详情中的“工作”只投影当前群可见的 Task/Run，两者读取同一事实，不复制任务或维护两套状态。
- 第一焦点：群消息和 Agent 单聊里的自然协作；第二焦点：右栏“工作”页签证明这些 `@` 或跨会话发送对应真实 Run、后台任务、审批或失败状态。
- 工作节点下钻：点击工作树的 Task 后，右侧面板原位切换成任务详情，不叠加第二个抽屉或模态框。详情只显示负责人、当前动作、阶段节点、最近进展、原始要求、按时间追加的补充和当前有效口径；不向普通用户展开 Run/attempt 内部结构。“补充要求”回到聊天输入框并携带 task 引用，“停止”只命中该 Task。
- 原型注释：场景名称只放在顶部选择器和副标题中；聊天消息区不展示设计说明、工具名或状态机解释，避免把评审标注误做成产品界面。
- 工作页签文案：不展示“为什么这样设计”的解释句，也不暴露 Run、Thread、steering、revision、delivery key 等实现术语；只显示用户可判断和操作的任务、负责人、语义进度、补充、结果及异常。开放式 Agent 工作不显示推测百分比，使用“当前动作 + 阶段节点 + 最近进展”；只有总量客观可知的批处理才能显示真实计数。
- 交互：主线可前后切换或自动播放；分支可通过选择器或箭头切换；“从 A 单聊安排 B 干活”中的轻回执可打开/关闭只读 Agent 对话；审批请求可直接跳到允许、拒绝或“加入群并继续”状态；工作节点可点击查看复用边界提示。
- 演示边界：这是本地交互原型，不会真正启动 Agent、审批、重试或后台任务；文案中的成功、失败和恢复仅演示预期产品状态。
