# RT-00：建立圆桌 feature gates 和计划验证底座

状态：待实施  
依赖：无  
建议负责人：1 名后端 / 平台工程师  
预计交付：1 个独立 PR

## 目标

在任何圆桌生产能力进入代码前，先建立服务端关闭边界。未完成的能力必须明确拒绝，不能因为部分代码存在就被调用，也不能返回模拟成功。

本任务同时保留现有计划验证器，确保后续拆分不会丢失验收标准、场景或依赖。

## 必须交付

### 1. 四个独立服务端 gate

定义固定枚举：

```ts
type RoundtableFeature =
  | "private_pair"
  | "public_collaboration"
  | "message_group"
  | "background_helper";
```

对应部署变量：

```text
ROUNDTABLE_PRIVATE_PAIR_ENABLED
ROUNDTABLE_PUBLIC_COLLABORATION_ENABLED
ROUNDTABLE_MESSAGE_GROUP_ENABLED
ROUNDTABLE_BACKGROUND_HELPER_ENABLED
```

解析规则：

- 未配置时为 `false`。
- `"true"` 为开启，`"false"` 为关闭。
- 其他非空值属于部署配置错误，启动时明确失败；不能静默当作开启或关闭。
- API 和 Worker 必须复用同一个解析函数，禁止各自读取并解释环境变量。
- 不把部署变量或完整服务端配置暴露给 Web。

建议把纯类型、解析器和断言放在 `@rakazo/core`，API 的 `AppEnv` 和 Worker 启动路径只消费解析结果。不要创建一套通用 feature-flag 平台。

### 2. 稳定的关闭错误契约

提供一个共享断言或错误类型，至少包含：

```ts
{
  code: "ROUNDTABLE_FEATURE_DISABLED";
  feature: RoundtableFeature;
  retryable: false;
}
```

要求：

- gate 关闭时，调用方得到可识别的结构化错误，不靠英文 message 判断。
- 错误不能伪装成权限不足、目标不存在或 Runtime 故障。
- gate 开启时断言无副作用。
- 本任务只建立错误契约和调用入口；具体功能入口在后续任务中接入对应 gate。

### 3. 计划验证器

保留并验证：

- `docs/roundtable/verify-implementation-plan.mjs`
- `docs/roundtable/verify-implementation-plan.test.mjs`

验证器必须继续拒绝：

- 缺少实施 owner；
- 重复任务；
- 未知或格式错误的 AC、场景和依赖 ID；
- 向后依赖和依赖环；
- 集成验收任务充当唯一实施 owner；
- 最终验收任务没有覆盖完整依赖闭包；
- C06、P05、F04 脱离指定 session-recovery owner。

## 建议修改面

实施者应先确认现有导出结构，预计涉及：

- `packages/core/src/roundtable-feature-gates.ts`（新增）
- `packages/core/src/roundtable-feature-gates.test.ts`（新增）
- `packages/core/src/index.ts`
- `apps/api/src/env.ts`
- `apps/api/src/env.test.ts`
- `apps/worker/src/index.ts`
- 必要的 API / Worker 启动依赖类型

可以根据仓库结构调整文件名，但解析逻辑只能有一个事实来源。

## 禁止范围

- 不实现 pair Thread、`message_bot`、`message_group` 或后台 helper。
- 不改 Web UI。
- 不新增数据库表或 migration。
- 不恢复 `run_subagent` 生产入口。
- 不引入第三方 feature-flag 服务。
- 不新增 Electron 或移动端代码。
- 不把 `scripted` 变成生产回退。
- 不修改 `.env`，不提交真实部署值或本机身份信息。

## 必须测试

1. 四个变量均缺失时全部关闭。
2. 每个变量可以单独开启，不连带开启其他能力。
3. 显式 `false` 保持关闭。
4. 拼写错误、`1`、`yes` 等非空非法值导致配置解析失败。
5. disabled assertion 返回固定 code、feature 和 `retryable: false`。
6. enabled assertion 正常通过。
7. API 和 Worker 都从同一解析器取得 gate，不存在第二份字符串比较。
8. 当前 31 个任务、39 条 AC、96 个场景仍通过计划验证。

最小验证命令：

```bash
pnpm --filter @rakazo/core test -- roundtable-feature-gates
pnpm --filter @rakazo/core check
pnpm --filter @rakazo/api test -- env
pnpm --filter @rakazo/api check
pnpm --filter @rakazo/worker check
node docs/roundtable/verify-implementation-plan.mjs
node --test docs/roundtable/verify-implementation-plan.test.mjs
```

## 完成定义

- 四个 gate 在未配置时全部关闭。
- API 与 Worker 使用同一解析和错误契约。
- 后续任务可以只通过 `RoundtableFeature` 调用 gate，不需要知道环境变量名称。
- 所有新增和受影响测试通过。
- 关闭 gate 时没有模拟结果或半执行记录。
- `git diff` 不包含密钥、真实用户数据、私有 URL 或无关格式化。

## PR 说明必须包含

- 四个 gate 的名称和默认值。
- 错误 contract 示例。
- API / Worker 的接入位置。
- 执行过的验证命令和结果。
- 明确声明：本 PR 没有开启任何圆桌生产能力。
