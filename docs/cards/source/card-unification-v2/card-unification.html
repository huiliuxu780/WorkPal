WorkPal 卡片统一 · CARD-01 目标结构

统一 Card Shell，不统一成万能业务类型。Web 从服务端投影渲染严格成员，不从字段组合、工具日志或文本猜类型、权限和状态。

本页是目标协议示意，不宣称这些类型已经作为生产 API 存在。

1 · 目标 InteractionView 与 DisplayBlock

type InteractionView =
	| InputRequestView        // requestInput(...)
	| ActionApprovalView      // requestApproval(...)
	| PlanReviewView          // plan_review：独立计划版本审阅
	| SessionControlView      // requestSessionControl(...)

type DisplayBlock = showContent(...)

目标 InteractionView 有四个独立成员；PlanReviewView（plan_review）只审阅计划版本，批准计划版本不批准任何工具调用、连接器或凭据，不经过工具授权链。

InputRequestView

requestInput(question · choice · form · secret · saved_item)

用户补充输入；Intervention resolution 是事实来源。

ActionApprovalView

requestApproval(tool · payment · outbound · routine · install · connect)

本人作出决定；外部结果由 ExternalEffect 或业务事务确认。

PlanReviewView

plan_review：计划版本审阅

独立成员，不进入工具授权链；批准计划版本不批准任何工具调用、连接器或凭据。

SessionControlView

requestSessionControl(takeover · return)

接管与交还桌面；只表达会话控制权。

DisplayBlock

showContent(markdown · table · chart · collection · media · html · task_status · page · voice)

只读展示；副作用必须另发审批。

2 · 三个状态所有者

Intervention

用户是否仍需回答或决定。每个请求按自己的生命周期结束。

Run

这一轮 Bot 是否仍在执行。Run 结束不自动作废 Interaction。

ExternalEffect / 业务事务

外部动作是否执行及结果是否确定，是付款、发信、安装和 Routine 的权威。

组合示例：Run 已停止且外部结果不确定时，显示“运行已停止，发送结果未确认”；不显示“已作废”，不提供重新执行。
