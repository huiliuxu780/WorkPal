# Task 18.3 Run budget progress

The Worker enforces the design defaults for tokens, active execution seconds, and tool calls. Interactive Runs have 200,000 tokens, 900 seconds, and 50 tool calls; unattended Runs have 500,000 tokens, 3,600 seconds, and 150 tool calls. Existing AgentScope child count and depth limits remain three and one. Enforcement reads durable `UsageRecord`, `agent.tool.called` events, and `Attempt` timestamps, so a Worker restart does not reset spend. Time waiting for a person to answer a budget card does not count toward execution time; completed and current Attempts do.

When an interactive Run exceeds a measured limit, it emits `budget.exceeded`, persists a waiting input card, and aborts the active AgentScope request. Only the Run owner may choose **increase**, **narrow**, or **cancel**. Increase persists a doubled limit for the exceeded dimension and queues the same Run with a new Attempt. Narrow and cancel end the Run; narrow asks for a new, smaller request. Unattended Runs fail with `reason=budget_exceeded`. A routine budget failure enters the delivery outbox so the Thread receives an explicit failure summary. Delegated Bot messages use the existing terminal-outcome reconciler.

The repository has no trusted provider/model price table. `UsageRecord` stores token counts and provider/model identity, but no verified USD charge. For an unknown model price, dollar cost remains **unknown** and `maxCostUsd` is not claimed as enforced; the other three limits still apply. A price source and a recorded cost with pricing version are required before enabling the USD gate. Estimates derived from token counts alone would present a false budget guarantee.

The Worker checks every ten seconds and the executor checks after each tool-call and usage event. These are post-event boundaries: an in-flight model call or already-started tool may run slightly past a token, time, or tool threshold before abort takes effect. The tool event is checked before its tool body starts. The budget path has targeted PostgreSQL and unit tests, including answer authorization and routine failure delivery (`run-budget-enforcement.postgres.test.ts`).

Real Java→API→PostgreSQL→Web browser acceptance now covers every budget dimension and both interactive choices, in `apps/web/e2e/budget-acceptance.spec.ts` plus the duration trace in `apps/web/e2e/agentscope-product.spec.ts`:

- **Token → increase** ("token budget breach lets the owner raise the budget and the same Run finishes"): a running Attempt crosses the 200k token budget through a persisted `UsageRecord`, the production `enforceRunBudgets` entry pauses it with exactly one `budget.exceeded` and one Intervention, a second authenticated user is rejected, the owner raises the budget, the same Run (same Task and prompt) re-executes on a new Attempt with an advanced fence and a persisted `budgetOverride`, a repeat scan does not re-pause on the old spend, and duplicate submissions replay or are rejected without re-enqueue.
- **Tool calls → narrow** ("tool-call budget breach narrows scope through the unified cancellation path"): real `agent.tool.called` events cross the 50-call budget, and narrowing cancels the Run with `budget_narrowed`, terminates the Attempt, revokes a live background task along the unified cancellation path, posts the narrower-request hint exactly once, settles the Intervention once, keeps the lease released, and never auto-creates a replacement Run — repeat scans and repeat submissions add nothing.
- **Unattended routine → failure + delivery** ("routine budget breach fails the Run and proactively delivers one summary"): a real Routine fired through `routines/testRun` crosses the 3,600-second unattended budget, fails with `budget_exceeded:duration_sec` without any Intervention, emits `budget.exceeded → run.failed → delivery.created → delivery.sent` in order, and the outbox delivers exactly one proactive summary message to the main Thread; repeated Worker scheduling never redelivers.
- **Duration → cancel** ("Java Run reaches a duration budget and Web cancels its waiting card"): the original interactive trace.

In these tests only measured facts are injected (persisted `UsageRecord` rows, real product events appended through the production writer, and Attempt clocks); Runs, Interventions, messages, deliveries and terminal states are all produced by the production paths. The E2E harness hosts the Worker's job handlers and budget sweep in-process, so this is not a separate Worker-process deployment test. `maxCostUsd` remains unenforced until a trusted price source exists.
