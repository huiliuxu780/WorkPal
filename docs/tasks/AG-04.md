# AG-04：提示词独立文件与统一组装

状态：`not-started`。依赖 [AG-03](./AG-03.md) 的完整场景契约与捕获接口稳定。

分支：`codex/ag04-prompt-files`，从 AG-03 的精确已推送 head 创建；初始 PR base=AG-03 分支。

## 用户已确认的交付

提示词按职责成为代码仓库里可直接阅读、修改的独立文件，调用处按场景选择、填入动态信息并组装。版本追踪使用 Git；比较通过 Git diff 和最终模型请求测试完成。

完整整理 P01–P14，不止提取一两个常量。不做提示词管理前端、独立数据库、在线发布系统、运行时版本切换或段落版本号体系。用户和 Bot 配置中的动态指令仍从原配置读取。

## 基线与真实组装顺序

1. 在任何搬移前，运行 AG-03 全部场景，保存一份最终请求基线并单独提交。
2. 基线必须来自 TS adapter → Java runtime → 本地模型 fixture 的真实最终请求。覆盖所有实际 RunTrigger、审批恢复、协作三种角色、四个辅助 scope、记忆/压缩/投递注入；只比较 compose() 返回值不够。
3. 当前 Java 顺序为 platform → content-trust-rules → turn-policy → bot-instructions → collaboration-context（chat）→ runtime-context。旧升级计划漏掉了 AG-06 trust rules，不得照旧顺序搬移。
4. AG-07 已用类型化 provenance 区分注入内容，不重新引入“靠正文前缀识别来源”的注册表。文本可以集中，来源判定继续使用类型化字段。

## 文件组织与加载

采用仓库根 `prompts/` 作为文本唯一来源，按职责分目录，保留 P01–P14 的索引映射，例如：

```text
prompts/
  README.md
  platform/platform.md
  platform/content-trust-rules.md
  policy/turn-policy-*.md
  chat/operating-guidance.md
  chat/reply-*.md
  collaboration/*.md
  context/*.md
  auxiliary/auto-review.md
  auxiliary/history-compaction.md
  auxiliary/group-router.md
  auxiliary/channel-judge.md
  feedback/*.md
```

这份目录是组织方式，不是要求每种场景新造一段文字；实际文件名由职责确定，在 README 列出每个 family 对应文件、调用方与条件。不要每句话拆一文件，也不要把所有家族再塞回单个巨型文件。

- 固定正文、现有模板和重复的固定反馈文案进入 `.md`；条件选择与格式化逻辑保留为有类型的 TS/Java 函数。
- 动态 task、Bot 名称/指令、当前时间、工具/技能目录、历史、记忆和结果不写入固定文件。模板占位符按明确字段替换，动态正文作为整体插入，不递归解析其中的模板符号。
- TS 使用适合当前 Node 构建的文本加载入口；保持可被 Web 使用的 core 导出无文件系统副作用。需要时采用既有 node 子路径或构建期打包，不把 fs 引进前端 bundle。
- Java Maven 将需要的同源文本作为 classpath resources 打入 jar。Java 不运行时读取开发者本机仓库路径；TS 不依赖 cwd 恰好为仓库根。
- Docker、打包产物和测试加载同一份原文；原有 platform-instructions 文本搬移后不再保留第二份手工维护副本。确需生成资源，生成规则入仓，生成物不能成为第二个编辑入口。
- 加载/模板函数只解决文本读取和填充；不建设通用模板语言或配置平台。

## 搬移与比较方法

1. AG-03 fixture 使用固定的测试身份、时钟和响应，建立完整的搬移前请求集合，先提交。
2. 按家族小批搬移，每批有可读提交。消息 role/name、顺序、正文、分隔符、空白、换行与工具集合保持不变。
3. 屏蔽字段只限请求 ID、临时路径、时间等已列出的不稳定元数据；不得 normalize/trim 正文后声称逐字节一致。
4. P01–P14 的每段分配稳定 ID，ID 用于源码索引与测试诊断，不在提示词正文添加新标签、不改变 wire contract。复用正文唯一来源，测试中的搬移前基线独立保留，不从待测文件反向生成期望值。
5. AG-03 场景表接上段 ID：每个 case 指明使用/排除哪些段，并继续比较真实模型请求正文，不能只有“文件存在/ID 存在”的测试。
6. 原有 AG-06 固定规则的独立原文断言仍保留；不因文本提取把测试与生产改成同源自证。

## 验收标准

1. P01–P14 全部有清晰文件/renderer/调用点索引；开发者可从场景找到源文件。
2. 固定提示词正文成为独立文件；executor/PromptComposer 不再承载成片的这些正文。
3. 全部可达场景的最终 system/instructions/prompt/history 消息内容与搬移前逐字节一致，工具集合相同。
4. 审批恢复、support/owner/handoff、channel 隐私、静默回复、辅助无工具、原生 helper 停用均保持现状。
5. 动态值含引号、换行、`${...}`、`{{...}}` 或 XML 标签时仍原样作为动态数据插入，既不漏替换也不二次求值。
6. AG-07 来源识别、ME-00 更新/删除后摘要重建不回归。
7. 从任意工作目录启动打包 Java jar 和 TS 应用均能加载文本；运行时镜像实际包含所需资源，不能只验证源码树。
8. Git diff 可以直接读到文本变化；本任务无前端页面、文本版本表或在线配置接口。
9. 最终真实请求比较为零正文变化；若遇到原有产品缺陷，另记 issue/后续任务，不把措辞修改混入搬移并更新基线放行。
