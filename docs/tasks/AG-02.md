# AG-02：核实并收紧 AgentScope 原生压缩边界

状态：`not-started`。本任务只定义实施与验收；进度以 [下一步工作清单](../next-work-roadmap.md) 为准。建议从已完成的 AG-01 代码开始，单独提交、单独评审。

## 目标

AgentScope 的原生 30/10 压缩继续服务于工作上下文及续跑，但不得绕过 WorkPal 后端的授权、持久化和审计流程写入原生长期记忆；压缩或消息卸载后，也不得把模型继续执行所需的内容变成不可读取的文件指针。

## 已核实的前提与待证问题

- 当前 `RuntimeEngine.java` 使用 `CompactionConfig.builder().triggerMessages(30).keepMessages(10).build()`，并设置了 `disableMemoryHooks()`、`disableMemoryTools()` 和 `disableFilesystemTools()`。
- 本机锁定的 `agentscope-harness-2.0.3.jar` 中，`CompactionConfig.Builder` 的 `flushBeforeCompact` **和** `offloadBeforeCompact` 默认值均为 `true`（已用 JDK 21 `javap -p -c` 核对）。原生 compactor 的相应开关分别通往 flush/offload 流程。
- 这些配置和调用路径说明**存在边界风险**，尚不能证明当前 WorkPal 执行一定写过 `MEMORY.md`、一定多调用模型，或一定产生了不可读取的指针。以真实运行证据决定修复范围。
- PostgreSQL 保存完整产品聊天及应用层 `history.compact` 摘要；AgentScope state 保存工作上下文。两个压缩层不能共用一个“已压缩”游标。

## 实施任务

1. **建立真实基线。** 沿用 Java runtime 的本地 OpenAI 兼容协议 fixture，在独立临时 state/workspace 下，用同一聊天 session 累积足够消息以触发原生压缩。捕获每次模型请求、请求用途或可识别内容、state 变化和 workspace 文件清单；证明测试确实进入压缩路径，而非只构造了配置对象。基线可以先失败，记录实测结果。
2. **检查原生记忆路径。** 区分正常回复、压缩摘要、压缩前 flush 的模型请求；检查 workspace 内 `memory/YYYY-MM-DD.md`、`MEMORY.md` 及其他原生记忆写入。若 flush 路径可触发，显式设置 `.flushBeforeCompact(false)` 并验证关闭有效。即使 fixture 因条件未触发实际写入，也要以测试或配置断言固定 `false`，避免默认值在生产中继续开放未经后端授权的写入路径。
3. **验证 offload 的可读性。** 构造足以触发 offload 的长消息/工具结果，检查压缩后模型实际收到的是正文、可读摘要，还是文件指针；继续一次模型回合验证读取途径。若指针依赖已禁用的文件系统工具或没有受控读回途径，显式设置 `.offloadBeforeCompact(false)`，并保留证明不再出现不可读指针的回归测试。不要仅凭开关默认值断言已经发生不可读卸载。
4. **验证续跑与隔离。** 同一 session 压缩后跨 Run 恢复，证明仍有最近 10 条附近的上下文和足以继续任务的摘要；至少覆盖第二次压缩或临界溢出一次。不同 tenant/bot/thread 的 state 不得串读。原生摘要不得写入或推进 PostgreSQL 的 `historyCompactionSummary/historyCompactedUpToSeq`。
5. **交付证据。** 记录修复前后文件清单、模型调用种类/次数、offload 读回结果、30/10 续跑结果及修改理由；把测试接入受影响的常驻 CI 路径。若实测与预期不同，更新任务说明中的结论，不扩大到新的长期记忆架构。

## 验收标准

1. **确实触发压缩：** Java 集成测试通过真实 `RuntimeEngine` → 本地模型 fixture，断言原生压缩发生、触发条件与摘要/状态结果可观察；不得用只验证 builder 值的单测替代。
2. **无原生记忆副作用：** 压缩前后 workspace 不新增 `memory/YYYY-MM-DD.md`、`MEMORY.md` 或等价原生长期记忆文件；没有压缩前记忆 flush 的额外模型请求。正常回复及必要的压缩摘要调用允许存在，并分别计数。最终配置显式关闭 `flushBeforeCompact`。
3. **内容可继续使用：** 对实际触发的 offload 说明发生条件和模型可见结果。若文件指针无法读回，最终配置显式关闭 `offloadBeforeCompact`；回归测试证明下一模型回合不会收到悬空指针。不能靠模型“猜出”被卸载内容算通过。
4. **30/10 续跑：** 压缩后在同一 session 的新 Run 能使用原生工作摘要和保留的最近消息完成一个带唯一标记的后续问题；第二次压缩或溢出重试后仍成立。无跨 session 污染，且不改应用层压缩游标或 PostgreSQL 完整聊天记录。
5. **工程交付：** JDK 21 `mvn -B -f services/agent-runtime/pom.xml package` 和相关定向测试通过；若触及 TypeScript，运行受影响包的类型检查与测试。交付说明包含可复现 fixture、前后证据、限制及 Git diff 检查，不含密钥、真实用户数据、私有 URL 或本机身份信息。

## 范围边界

- 本任务处理 AgentScope 原生压缩安全与可恢复性；不实现应用层 `history.compact` 的新策略、事实/分片/汇总长期记忆或记忆抽取 Hook，那些属于后续 ME 项。
- 不关闭原生压缩来规避验收；保持现有 30/10 触发与保留语义，除非真实测试证明它本身不能正确续跑，并另记设计偏差。
- 不新增模型可调用的文件、Shell 或记忆工具来掩盖不可读指针；读取能力必须遵守既有后端权限边界。
