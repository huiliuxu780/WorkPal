# CARD-01F：`@我`（提及我）角标与语义

状态：`not-started`

父任务：[CARD-01 卡片统一与拓展](./CARD-01.md)

来源：2026-10-28 CARD-01D 复审裁决——CARD-01D 的验收原文要求"未读、待处理、`@我` 语义在测试中互不混用"，但仓库没有任何"提及本人"的数据模型、RPC 字段或 UI。负责人决定不在 CARD-01D 内补实现，拆到本卡；CARD-01D 的验收表已同步改为只要求未读与待处理。

## 用户结果

用户能在会话列表看到第三种提醒标记：它既不是"未读"（数字/点），也不是"待处理"（pending Interaction 计数），而是"有人在消息里明确提到了我"。打开会话或处理后标记按规则清除，并且不会把 Bot 之间的消息、后台进度更新算成 `@我`。

## 必须先定的产品语义（未定，不能直接写实现）

- 谁能提及用户：Bot 对用户的提及、群内其他成员对用户的提及，还是两者都要？
- 提及如何存储：消息 inline 已有 `bot_mention`（Bot 之间的结构化提及），用户提及需要一个对应的结构化 inline 与投影字段，不能靠正文正则。
- 清除规则：打开会话即清除、还是需要看到那条消息？`@我` 与未读、待处理三者的叠放与优先级。
- 与 CARD-01D 的 attention queue 的关系：`@我` 是否也进入队列（当前裁决只要求角标，不要求进队列）。

## 原型

N3（`docs/cards/source/card-unification-v2/mockup/cards-hifi-v4/b-alerts.html`）给出了三种标记的文字+形状+颜色示意。按前端铁律，实现前必须先更新/新建可运行原型并确认三种标记在同一列表里的共存状态（含 390/375、深色、键盘），确认前不得改生产页面。

## 范围（原型确认后生效）

- `packages/contracts`：用户提及 inline 与未读/`@我` 投影字段
- `packages/db`：按会话统计未读与 `@我` 的有界查询
- `apps/api/src/router.ts`：返回 `@我` 计数的适配
- `apps/web`：侧边栏第三种标记与可访问标签
- 对应 API、Web、e2e 测试与 390/375/深色/键盘截图

## 禁止

- 用正文正则或字符串匹配推断"提及"
- 把 Bot 间消息、后台进度、终态事件算成 `@我`
- 与未读或待处理复用同一视觉元素（必须文字+形状+颜色区分）
- gate 关闭时改变现有未读或 ActivityList 行为

## 验收

- 只有真实的用户提及产生 `@我`；Bot 间消息与进度更新不产生。
- 未读、待处理、`@我` 三种标记在同一列表共存时互不混用，DOM 与可访问名称可区分。
- 清除规则按最终产品定义生效，处理后计数同步。
- 390px、375px、深色模式、键盘可达；gate 关闭时旧行为不变。
