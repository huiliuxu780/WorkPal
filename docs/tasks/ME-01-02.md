## 1. 用户完成后能做什么

1. 明确说“记住这个”，或在现有 Knowledge 入口创建记忆；随后能查看来源、作用域，逐条纠正和删除。
2. 在新的 Thread 中使用已经确认的记忆；自动发现的习惯先作为候选展示，由用户确认后生效。
3. 同一个事实纠正或删除后，旧分片、汇总、检索索引与工作上下文不继续把旧记忆作为有效记忆注入。
4. 长对话经过至少两次压缩后仍能接着做未完成的任务，知道哪些外部操作已完成，不重复发送。
5. 旧 Markdown 记忆、现有聊天记录和已有权限继续可用，不要求用户手工重建全部数据。

事实、分片、汇总、候选提取、上下文预算、压缩和 UI 是本批完整范围。不能仅建表/API，或只交一个新记忆页面就标完成。

## 3. 完整实施范围

### M1. 事实、证据、纠正与作用域（ME-01）

- 实现 `MemoryFact` 和 `MemoryEvidence`、必要修订、索引及事务仓储。事实有稳定 ID、actor/Space、Bot/user/Space scope、canonicalKey、正文/受限 literalValues、origin/state、revision、有效期、纠正关联、来源 Run 和审计。
- active 行按受权范围去重；语义冲突不能只凭正文 hash。`scopeKey` 由后端已校验的实体 ID 构造。不同作用域冲突保留来历，先应用用户明确纠正/直接编辑；同等来源时明确的 Bot 范围覆盖通用用户/Space 默认，不能用模型推断覆盖用户确认。
- 用户直接编辑或可信入口明确“记住 X”可单次激活；有歧义则候选确认。自动推断不得走这条捷径。正文归纳表达；命令、路径、称呼等必要原值放入受限 literalValues 并作为数据转义。
- evidence 使用可信 `authorUserId/originKind`、Thread/generation/seq/messageId；不凭 `role=user` 认定人工意图。去重摘要需要时用服务端 HMAC，不存可猜测原文的普通 hash 作为隐私替身。
- 写操作携带 expected revision；并发纠正返回可操作的版本冲突，不静默覆盖。纠正生成新有效版本并保留 superseded 关联。
- 个人事实只对有权 actor 可见；同 Space 共享须逐条人工 promote、检查目标权限并保存来源关联。跨 Space 共享不自动开放。

### M2. 分片、汇总与受权读时注入（ME-02）

- `MemoryShard` 按 `(spaceId, scopeKind, scopeKey)` 唯一，version 单调；`profileMarkdown` 是可重建投影，`profileVersion == version` 才可读。修订/证据分页读取，不往单列 JSON 无限追加日志。
- 事实变化、分片递增、审计与汇总 outbox 同事务提交。Worker 作业按版本幂等；旧作业不能覆盖新纠正。
- `ContextSummary` 固定接收者与输入分片 `sourceVersions`、生成模型、prompt 版本和 token 估算。只归纳当前可见 active 事实，验证结构、来源覆盖和敏感内容，再 CAS 发布。任一输入版本或权限不匹配即不注入旧汇总。
- 汇总模型独立于主聊天模型配置；提取和汇总均经 AgentScope 的无工具辅助执行路径。辅助 scope 保持工具集合为空，不靠模型读文件或获得数据库/连接器权限。
- 汇总未就绪时确定性拼接有权 active 事实；外部语义 provider 只作可重建索引。provider 故障不阻断第一方读取。
- 统一装配旧文档、新汇总和补充事实：迁移期总量最多 4,000 估算 token，旧文档最多 2,000，新内容最多 2,000；其中汇总最多 1,200、补充事实最多 10 条，子预算不互借。旧文档退出自动注入后总量收至 2,000；小窗口按可用预算缩减。32 KiB 只是读取防护。
- 同一装配函数负责选择、截取、转义、来源身份和选中/省略统计；不能在 executor、memory-context 和 Java 分别叠加独立上限。历史及记忆继续在数据位置，保留 AG-06/AG-07 的信任边界。

### M3. 自动提取与候选闭环（ME-02）

- 人工回合完成、明确纠正/记忆编辑触发增量作业，周期作业补漏；复用现有 Worker/Job，以 actor、Thread、generation、highWatermark 和版本去重。
- 从 PostgreSQL 读取有界可信用户消息。模型只产严格候选结构；分析阶段不写事实或分片。后端核对证据 actor/权限/generation、秘密、冲突和正文后事务提交。
- 推断习惯至少四个不同 Thread 的独立用户证据才达到候选展示门槛；同 Thread 复制、Bot 复述、工具/网页/webhook、wake/ack 不增加计数。四条证据仍不等于激活，须用户确认。明确记忆的单次激活规则与此分开。
- 候选可确认、拒绝、纠正，未确认内容不进入任何记忆注入。拒绝/删除记录阻止同一旧来源被周期扫描反复重新推荐；新的明确用户指令可建立新版本。
- 提取模型和汇总模型分别可配置，记录实际身份与用量；应用历史压缩仍遵循 M4 的主对话模型固定规则，不能混用三种调用。
- 扫描量、频率、token、单用户每日调用/费用与并发为服务端配置，给出实际默认值及单位。保留测试 Space 定向启用和暂停自动推断的配置，但必须实现并通过启用路径，不能靠默认关闭交付空功能。
- `WorkPalMemorySignalHook` 只发有界生命周期元数据；不写原生记忆，不复制原始工具结果，不阻塞模型。核实锁定依赖实际事件，不假设存在专用压缩完成 Hook。

### M4. 应用层与原生压缩完整增强（ME-02）

- 应用 `history.compact` 持久化可审计摘要修订及覆盖范围：threadGeneration、seq/锚点、上一修订、来源 Run、实际模型身份、策略、`includesToolResults`。
- 入队时固定覆盖批次尾部对应的最近已完成主对话 Run 的 `sourceRunId/modelProvider/modelId`；执行时按该身份取当前凭据。入队后用户改 Bot 模型不改变作业模型；凭据不可用明确失败，不静默换模型、不推进游标。
- 触发基于可用历史预算：模型窗口扣除系统提示、当前实际工具 schema、用户输入、输出预留和余量。计数不可知时明确使用估算或现有消息阈值，不能伪报精确 token。
- 实现 `disabled / background_nowait / background_wait_if_needed / sync` 四种模式；普通回合 nowait，预计超限时有界等待同 generation 作业，不足再同步补救，必须拿到摘要才能裁剪/交接的内部路径 sync。原始 PG 消息正常提交，不先等待摘要。
- start/persist 的绝对与比例余量配置必须对应明确的字节/token 和覆盖语义。并发、失败、取消、重试、Clear 后迟到作业均由 generation/版本控制，不能漂移游标或丢原文。
- 当前产品消息未覆盖完整工具结果，`includesToolResults=false`；不能为声称“完整执行历史”擅自持久化所有原始工具输出。摘要须保留目标、已完成动作/operation 引用、未完成事项、必要资源和下一步。
- 原生压缩仍只修改 AgentScope state。解决 AG-02 记录的动态 token cutoff 与“30/10”字面值偏差：按实际模型窗口定义并测试 trigger/keep token；若保留消息数语义，必须配置出真实语义。记录两层各自的预算与续跑覆盖。
- 保持 flush/offload/原生工具结果卸载关闭及既有有界输出；不借本任务恢复 helper。压缩后仍超限给明确错误与可操作的缩短输入、调整窗口或新 Thread 建议，不默默删原文或把 Task/Run 当新会话。

### M5. 删除、清空、迁移与兼容（两项共同验收）

- 删除后立即从事实、分片/汇总、旧记忆映射、全文/语义检索与运行注入排除；同事务写删除状态、版本与清理 outbox。外部索引清理失败可见且可重试，不能重新回流到模型。
- 删除操作处理旧记忆修订中的正文；审计保留必要 ID、actor、版本和删除动作，不复制被删正文。按现有备份保留策略记录离线备份边界，恢复流程需重放删除记录以防复活；不宣称离线备份即时擦除，也不把 DEP-01 主机备份改造混入此批。
- 对含派生记忆的应用/原生摘要维护可失效的依赖或等价版本机制，保留 ME-00 的可信历史重建；覆盖 old→new、old→none、第一次升级旧会话，不能只删摘要而永久丢掉早期正常对话。
- “删除记忆”不等于删除用户原始聊天。仍保留的独立聊天内容可能再次进入正常历史；UI 和测试准确区分这两种操作，不声称真实模型已忘记。删除标记应防止后台从同一旧证据自动重建已删除记忆。
- Clear Thread 保留用户已确认的独立记忆，令来源引用不可访问；取消提取并用 generation 拒绝迟到结果，移除只有该 Thread 证据的未确认候选。删除 Bot/Space 延续现有实体清理与外部索引清理。
- 旧 `memory.list/update/exportMarkdown` 保持可用；旧 Markdown 不自动伪装成高置信原子事实。逐条用户确认后转为 legacy_import；旧文档为旧格式兼容写入口，新事实为新结构入口，禁止双向自动同步。确认迁移的同一内容不双重注入，拒绝/撤销语义明确。
- 完成 expand/backfill/read-switch 路径和回退演练；迁移在空库/带旧文档库可执行，旧数据和中英文可读。部署时不对全部历史同步调用模型。

### M6. API、工具和现有页面（两项共同交付）

- 提供受权 `memory.facts.list/get/confirm/correct/delete/promote`、`memory.factEvidence.list`、`memory.summary.get` 或统一 API 层中的等价类型化接口；revision、scope 和业务错误对 Web 可用。
- 改接 `remember/save_memory/recall_memory/forget_memory` 到同一后端服务，不能保留一条绕过逐条删除的旧隐藏写路径。普通 Bot 对话、可信 messaging 入口、直接编辑的行为一致且 actor 来源准确。
- 在现有 Knowledge 页面和组件体系提供已记住/待确认/已失效、来源/更新时间/作用域、编辑纠正、确认/拒绝、删除及逐条共享；旧文档清楚标识。加载、空列表、版本冲突、保存失败和索引清理中有真实状态。只在事务成功后显示“已记下”。
- 指标覆盖提取/汇总/压缩的模型、耗时、估算/实际 token、调用成本、失败、游标滞后、候选确认/拒绝、纠正、过期拦截和索引清理延迟；接现有日志/指标，不另建一个运营平台。
- 提示词全部走 AG-04 根目录和单遍 renderer。新片段/工具字段有意变更要写明，保留独立 trust-rules 断言，不能整体刷新黄金样本掩盖漂移。

## 4. 本地连续实施顺序

M1 事实/证据 → M6 基础 API/显式记忆 UI → M2 分片/汇总/注入 → M3 提取/候选 → M4 压缩 → M5 全路径删除与迁移收口。必要时交错实现，不要求先写出暂时不可工作的层再凑集成。

每阶段提交本阶段实现和有价值的定向测试，随后继续；不以线上使用量、另一个小 PR 的 CI、文档单独合并为中间门槛。跨模块协议、数据库和 Java 需要改就完整实现，不用前端模拟或永久关闭能力替代。
