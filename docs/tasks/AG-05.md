# AG-05：每次模型请求的真实工具可见性

状态：`in-progress`（实现与本地定向门禁完成，待 AG-08 同分支连续提交后统一 PR）。分支 `codex/ag05-tool-visibility-recovery`，独立 worktree `WorkPal-ag05`，基线 `main @ a39b25d`。交付说明：[ag05-tool-visibility.md](../ag05-tool-visibility.md)。可与 MR-01-R3 并行；共同修改 executor 时各自提交清晰，合流时验证提示词/工具面。

## 要做成什么

同一个 Run 内，下一次模型请求只看到此刻真实可用的工具。权限、连接器/resource、执行阶段变化后，工具列表与实际能力同步；后端仍执行当前授权。用户不会被模型引导去用已撤销的工具。拒绝后的 pending-call 消费与长期 Thread 恢复单独由 AG-08 交付，不作为 AG-05 的完成条件。

## 当前事实与前置取证

AG-03 已有 TS adapter→Java jar→本地协议 fixture 的真实捕获和生产 PG 场景。`RuntimeEngine` 在创建 Run 时构建 Toolkit/allowlist；必须核实所锁定 AgentScope 版本在每轮模型调用前的工具刷新机制，包含它自行注册的 native 工具。请读实际依赖源码/字节码和执行路径，不能凭配置名推断能力。

先建立同 Run 至少三轮的红色证据：初始可用→撤销→重新授权/阶段恢复；每轮记录最终请求中的名字与 schema、调用结果和真实副作用。fixture 只回答确定性响应，不把它称作真实模型抗注入评估。

## 完整实施范围

1. 定义并实现每次模型调用前的工具集刷新点及后端→runtime 更新契约，说明权限快照、刷新时机、Run/Attempt/session 归属。
2. 同 Run 变化覆盖：连接器撤销/恢复、绑定 resource 权限/版本变化、当前阶段工具子集改变。工具 schema 与名称同步，不能只过滤名字而保留旧 schema。
3. 覆盖后端工具、技能入口、native Plan 工具；AG-01 辅助 scope 始终无工具。原生 helper 委派继续按生产停用契约，不借此重新开启。
4. 已开始的工具执行与下一轮可见性分开定义：授权在真实执行前按当前状态检查；移出列表不伪装成已执行成功；进入列表也不扩大凭据/资源。
5. 跨 Run 恢复时更新当前工具面，不把历史会话的工具注册当作本次授权。后台已启动任务的完成/回收能力按既有契约保留。
6. 提示词通过 AG-04 文件/renderer 更新，能力宣告与最终列表一致。正常工具执行、审批继续、历史压缩、记忆清除、来源标注、Worker 路径不回归。
7. 若依赖确实不支持必要刷新，交付可复核的最小依赖实验、可实施的接口改动和成本；不要把“后端拒绝”或“下一 Run 生效”标成此需求完成。AgentScope 仍是唯一生产执行器，不能增加另一套执行器代替。

## 验收

- [x] 同 Run 三轮真实请求证明移除与重新加入，不靠重新建 Run、清 Thread 或换 sessionGeneration 通过。
- [x] 撤销后发出的下一轮请求不含被撤工具；被保留工具名/schema 完整正确。
- [x] 当前 resource/版本变化被实际工具身份与授权识别，合法工具仍能真实完成。
- [x] 模型直接调用已不可见工具时由执行边界拒绝，provider 请求数零；拒绝可观察且不冒充工具成功。
- [x] 普通聊天、routine、delivery、组路由/判断器、审批恢复、技能与 native Plan 的资格分别有证据；辅助 scope 工具集合严格空。
- [x] 两个 Bot/Thread/用户同时运行，工具注册/刷新不串；生产停用 helper 不回归。
- [x] 真实 PG executor 与 jar fixture 的一条连续权限变化旅程；单元只补核心规则，不能替代链路证据。
- [x] AG-03 场景 + AG-04 最终请求基线有意差异清楚，AG-01/02/06/07、ME-00、MR-01 相关回归通过。
- [x] 受影响 TS 包和 Java check/test 通过，常驻 CI 接线准确；测试数字与原始可复核记录一起提交。
