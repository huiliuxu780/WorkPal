## 交付目标

把 WorkPal 已支持的 14 类场景变成可执行的“触发 → 提示词族 → 最终模型工具集合 → 执行结果”契约。开发者修改提示词、工具选择或入口时，可以运行测试知道哪些场景受到影响。

这是完整场景覆盖任务，不止做代表样例；同一场景里的不同触发和关键分支都必须有明确 case ID。采用本地确定性模型 fixture，无付费模型调用。

## 实施结构

- 建议 `packages/adapters/src/scenario-contract.test.ts` 与 `__fixtures__/scenarios/`。case 需包含稳定 ID、触发、协作角色、scope、预期提示词族、精确工具名集合、预期结果及证据测试链接。
- 复用既有 executor、真实 TS adapter、Java jar 和本地 OpenAI 兼容 fixture。场景编排和权限断言可在合适的 TS/PG 层执行；最终模型可见工具必须在实际发往模型的请求边界捕获。
- 每行可以链接多个测试，不要求把所有入口塞进一个超级测试。共享 fixture 生命周期和基础 seed，避免每条重复构建 jar。
- 初始用稳定标记识别提示词族 P01–P14，AG-04 后接到段 ID。断言包含/排除关系与组装位置，不把动态 ID、时间或用户数据写进快照。
- 工具名集合同时含后端工具和原生工具；明确排序后精确比较。权限变化的测试先证明工具原本可用，再改变权限/连接状态并验证执行结果。运行内下一次模型调用是否重新裁剪工具属于 AG-05，本卡记录当前事实。

## 场景覆盖清单

| ID | 必须执行的 case | 必须证明的行为 |
| --- | --- | --- |
| S01 | user、follow_up、reaction；有/无技能与连接器 | 当前用户工作和指令送达；工具集合与配置对应；普通授权工具可执行；reaction 按当前实际入口分类 |
| S02 | 显式 mention、reply target、语义 router、lead fallback | 成员选择优先级；router 的 `turn-routing` 请求无工具/历史；选中 Bot 进入真实工作链路 |
| S03 | created | 介绍提示词；模型可见工具符合当前非交互规则；无实际工具副作用 |
| S04 | routine，有结果/静默两分支 | 不含 schedule_create；原生 Plan 不提供；真实结果与 NO_RESPONSE 各自正确落库 |
| S05 | webhook、messaging、skill、cloud_agent、spawn、call_end 分别建子 case | 每个实际可达入口的输入、提示词、工具面；webhook 写操作走既有审批；语音/消息特有规则生效 |
| S06 | support、handoff_owner、owner 收到结果继续 | 所有权与最终回复对象正确；support 不出现 Plan/helper；协作工具仍按现有授权执行 |
| S07 | 生产停用请求；既有 Java seam 委派回归 | 生产入口不提供 helper 工具，直接调用也不能启动；已有后台结果完成/投递路径保留。两种证据必须分开标识 |
| S08 | outbox 触发的 delivery，成功/失败结果 | 无工具/skills；结果送达当前 Thread，重复 claim 不重复投递，明确这是 Worker 路径 |
| S09 | approval allow、deny、恢复前权限变化 | 同 Run 恢复；批准动作按记录回放一次；当前权限拒绝仍生效；deny 不执行副作用 |
| S10 | auto-review pass、ask、调用失败 | `auto-review` 无工具/历史；输出与既有 pass/ask 行为一致，不替代强制审批 |
| S11 | history.compact 有效摘要、无有效摘要 | `history-compaction` 无工具/历史；有效摘要才推进应用层游标，与 Java 工作摘要区分 |
| S12 | Bot/user 持久记忆、语义召回、更新/清空 | 类型化 application-context 数据送达；不同作用域各自正确；复用 ME-00/AG-07 删除与续跑证据 |
| S13 | computer/browser 的可用/不可用配置，连接器连接/断开 | 实际工具选择与执行结果；连接器断开或权限撤销后旧调用不会产生真实操作 |
| S14 | channel judge ignore/engage、异常静默、后续 messaging Run | `team-chat-judge` 工具严格为空；频道隐私规则送达；不注入个人记忆 |

S05 中若某名称在当前 main 只存在于 union、没有生产入口，必须以代码路径和触发测试证明“声明存在、入口未实现”，在矩阵列为 unavailable，并测试不会冒充已支持；不能写 mock 成功算覆盖。该情况属于交付发现，其他可达子项继续完成。

基线核实还须枚举实际 trigger union，对照 case 清单查漏。resume 等若是恢复动作而非新触发，归入 S09；每个实际 trigger 必须归属于明确的场景子 case，不因旧矩阵没列出而遗漏。

## 验收标准

1. S01–S14 全部有 case ID 和可运行证据，S05 不合并成一个笼统样例。
2. 每个模型调用 case 断言最终 scope、提示词族和精确模型可见工具集合，含原生工具。
3. 至少覆盖一次完整合法工具执行、一次真实审批恢复、一次连接/权限变化后的拒绝及零副作用；这些经过生产 executor/DB 链路，不用返回值 mock 代替。
4. S07 清楚区分生产停用契约和测试 seam，不重新启用 helper。
5. S09 记录同 Run 的恢复与自动 Attempt retry；不与 MR-01 的新 Run 混淆。
6. 全部测试默认离线运行；没有凭据也能执行，不把未运行记作通过。
7. 矩阵每行 Evidence 可定位到测试/case；P01–P14 清单按当前代码纠正，无过期审计结论。
8. 至少选择一个工具集合断言和一个场景角色断言做局部破坏验证，确认失败后还原；不必给每条测试做破坏验证。
9. 现有 AG-01/02/06/07、ME-00 相关行为不回归。发现真实产品缺陷，记录复现、影响和归属，不通过改预期掩盖。
