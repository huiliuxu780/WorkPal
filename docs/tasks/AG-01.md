# AG-01：团队聊天判断器的辅助执行隔离

状态：`not-started`。本任务只定义工作与验收；实施状态以 [下一步工作清单](../next-work-roadmap.md) 为准。

## 目标

团队聊天参与判断器只负责输出是否参与的 JSON 决定。它的一次模型请求不得暴露后端工具或 AgentScope 原生工具，包括 Plan、Skill、子 Agent 和后台任务工具。现有聊天 Run 的工具能力不受此辅助调用影响。

## 已核实的前提

- `apps/api/src/team-chat-judge.ts` 发送 `tools: []` 和 `history: []`，但没有发送 `executionScope`。
- `packages/adapters/src/agentscope-runtime.ts` 把缺省 `executionScope` 序列化为 `chat`；`services/agent-runtime/.../RunRequest.java` 也把缺省范围当作 `chat`。
- `RuntimeEngine.java` 在聊天范围允许原生 Plan，并把 `load_skill_through_path` 加入可见工具列表。仅传 `tools: []` 因而不足以证明模型没有工具。
- 现有 `team-chat-judge.test.ts` 以模拟 runtime 测提示词、解析和用量写入，没有捕获 Java 实际发给模型的工具列表。

这证明**隔离配置存在缺口**。模型实际收到的工具集合以及是否曾调用工具，仍须由第一项验收测试确认；不要把代码推断写成已观察到的历史事件。

## 实施任务

1. **先建立基线证据。** 用仓库现有的本地模型协议 fixture，把一次真实的判断器调用穿过 TypeScript adapter 和 Java runtime，捕获最终模型请求中的 `tools` 名称。让“必须为空”的断言先在当前实现上给出明确结果，保存测试输出的工具名集合；不依赖付费模型。
2. **显式标注辅助范围。** 给判断器请求传专用 `team-chat-judge` 范围，并同步更新 `AgentRunRequest.executionScope` 类型、序列化、Java `RunRequest` 的允许值与范围测试。调用仍使用独立的临时身份、空历史和空后端工具，不共享主聊天 session。
3. **在 Java 边界强制无工具。** 所有辅助范围（现有 `auto-review`、`history-compaction`、`turn-routing` 和新增判断器）都不得把 Plan、`load_skill_through_path`、子 Agent、后台任务或后端工具暴露给模型。不能只在提示词里写“不要调用工具”。对辅助请求若意外携带后端工具或 Skills，应拒绝请求或在可信边界明确清空，并以测试固定选择；不得静默让其进入模型请求。
4. **补回归并保持原行为。** 判断器仍按现有 JSON 规则解析决定，失败时保持静默；用量记录继续写入。普通聊天的获授权工具、Plan、Skill 和子 Agent 行为保持现有策略，其他三个辅助范围继续隔离。

## 验收标准

1. **真实边界：** 一个经过 API 判断器 → TS adapter → Java → 本地模型 fixture 的测试捕获到 `executionScope="team-chat-judge"`，最终模型请求的工具集合严格为空；断言覆盖后端和原生工具，不能只检查 `AgentRunRequest.tools=[]`。
2. **辅助范围：** 对 `auto-review`、`history-compaction`、`turn-routing` 和 `team-chat-judge` 分别验证：即使请求错误地要求可用工具或自动 Plan/委托策略，也不会产生可调用的模型工具。选择“拒绝”时要断言明确失败，不能把失败伪装成判断结果。
3. **聊天不回归：** 普通 `chat` 请求在已有授权和 TurnPolicy 下仍能看到应有的后端工具、Plan/Skill；禁用 Plan 或委托的既有测试保持通过。
4. **业务输出不回归：** 判断器的 `act=false/true` 解析、失败默认静默、用量记录和请求超时行为通过定向测试。测试不使用真实团队消息、凭据或付费模型。
5. **交付证据：** 记录修复前后模型可见工具名集合、受影响的 TypeScript/Java 类型检查与定向测试结果，并检查 Git diff 没有密钥、真实用户数据、私有 URL 或本机身份信息。

## 边界与排除

- 不改判断器的参与规则、提示词措辞、模型选择、消息投递或 UI。
- 不把 Pi、`scripted` 或另一个执行器作为生产回退。
- `flushBeforeCompact`、原生记忆写入和工具结果卸载属于 **AG-02**，不以本任务的工具隔离测试代替。
- 若第一项测试发现当前模型工具集合已为空，仍给判断器显式的专用范围并保留回归测试；Java 侧只做测试证明需要的最小防御性修改，在工作清单中记录与原假设的偏差。
